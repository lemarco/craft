# 0.6.2 (draft)

Patch release: **structural limits product layer** (R1–R4 docs + guards), Postgres cap store integration tests, directory RYW after multi-Raft rebalance.

## Product / DX

- **R1** — `MAX_RAFT_COMMAND_BYTES` (512 KiB); client and leader wire reject oversize proposes (`CommandTooLarge`).
- **Multi-Raft on `TrembitaApp`** — `add_raft_groups`, `query_linearizable`, `query_keyed_linearizable`, `propose_keyed`, `run_cross_shard_2pc`.
- **`OpCtx` consensus** — [`consensus.rs`](../../crates/trembita/src/capability/consensus.rs): `require_app`, linearizable query/propose, keyed saga / 2PC from handlers.
- **R3** — `DirectoryPolicy::ReadYourWrites` default for `CapManifest`; `directory_policy` / `directory_retry` on builder; rebalance directory boost + publish in assembly.
- **R4 guard** — `trembita doctor` flags capability handlers using store APIs without `OpCtx::require_store`.
- **Docs** — [structural-limits](../scenarios/structural-limits.md), [write-scaling](../scenarios/write-scaling.md); stateful-workers showcase notes (cap store vs Raft SM).

## Optional integrations

- **`trembita-capstore-postgres`** — integration test behind `#[ignore]` (heavy CI); see crate README.

## Upgrade

```bash
cargo update -p trembita
cargo check
```

No breaking API changes intended for 0.6.x apps using `CapManifest` + `TREMBITA_*` env boot.
