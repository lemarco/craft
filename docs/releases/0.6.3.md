# 0.6.3

Minor release: **product scale wave** (B-28–B-41) — elastic join, join readiness, R3 directory ops, coordination growth presets, founder/local 3-node DX, gateway session issuer/verifier split, durable mailbox + `on_leader` + Postgres schedules.

## Product / cluster

- **B-28–B-32** — auto cap group scale, cluster session cookies, ingress `/health` vs `/ready`, product scale doctor, coordination-scale queues and multi-Raft on `TrembitaConfigure` / env.
- **B-33** — boot product-scale introspection (`GET /introspect/product-scale`), `doctor --preflight`, multi-node CapHost remote spawn hardening.
- **B-34** — elastic join + HTTP LB proof (`e2e/elastic_lb.sh`, `trembita-tools` e2e-elastic).
- **B-35** — join readiness pipeline (`join_phase` on `/ready`, `/introspect/join-status`).
- **B-36** — R3 rebalance visibility, `/introspect/directory-r3`, sticky session recovery.
- **B-37** — `CoordinationGrowthPreset`, `TREMBITA_COORDINATION_PROFILE`, manifest queue auto-shard wiring.
- **B-38** — scale scaffold DX (`doctor --explain-scale`, `new --profile`, jobs `task.rs` template).
- **B-39** — local 3-node cluster (`scripts/local-cluster.sh`, `trembita dev cluster-up`, optional nginx LB).
- **B-40** — gateway auth split: `SessionIssuer` / `SessionVerifier`, **`trembita-gateway-auth`**, `examples/oauth-gateway`.
- **B-41** — durable mailbox spool, `on_leader`, **`trembita-schedule-postgres`** / `PgScheduleSource`.

## Docs

- Scenario tables and `bXX_*` regression filters: [capabilities](../scenarios/capabilities.md), [testing-coverage](../testing-coverage.md), [status](../status.md).

## Upgrade

```bash
cargo update -p trembita
cargo check
```

New optional workspace crates: `trembita-gateway-auth`, `trembita-schedule-postgres` (enable via `trembita` features / `TrembitaConfigure` as in crate READMEs).

No intentional breaking changes for 0.6.x apps using `CapManifest` + `TREMBITA_*` env boot; review [gateway-cluster-auth § B-40](../decisions/gateway-cluster-auth.md) if you rotate session secrets or split issuer/verifier processes.
